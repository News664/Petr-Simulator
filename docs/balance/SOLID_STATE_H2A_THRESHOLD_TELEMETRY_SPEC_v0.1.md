# SOLID STATE — H2A Threshold Calibration Telemetry
## Version 0.1

## Purpose

The first human playtest produced several observations that are plausible but too
small-sample to balance directly:

- only one of five manual lives ended;
- CHR and INT appeared able to rise above 15;
- MNY and SPR appeared flatter or slightly downward;
- housing/moving events felt repetitive;
- faction chains were hard to perceive and safe opt-out felt frequent.

The threshold calibration should therefore answer **two questions at once**:

1. Which existing FIX threshold profile best restores a playable ending economy?
2. What content/attribute problems are actually measurable before the next creative
   Pressure & Tone patch?

This document extends measurement only. It does not authorize content changes.

## Control arm

Use the current authored repository as `CURRENT_AUTHORED`.

Do **not** use Phase 1.1 `ORIGINAL_REFERENCE` as the current control. Some canonical
gates changed after Phase 1.1, so that arm is historical, not today's baseline.

LOW/MID/HIGH continue to use the retained reversible threshold-rewrite machinery:
- rewrite assigned event FIX gates;
- rewrite schedule validity conditions pointing to those events;
- never edit canonical event JSON.

## Sampling

Primary:
- 3,000 runs per arm;
- four arms: CURRENT_AUTHORED, LOW, MID, HIGH;
- 12,000 runs total;
- same base seed across arms;
- species stratified equally;
- uniform-three compatible talent diagnostic;
- `ARCHETYPE_SET` allocation;
- uniform family weighting;
- max age 120.

Reason for ARCHETYPE_SET:
Phase 1.3/H2A diagnostics and actual human setup behavior use more concentrated
player-like allocations than the old Phase 1.1 balanced-random threshold arm.
This is a current H2A calibration, not a rewrite of historical reports.

## Visible-stat snapshots

Record visible stats at:
- post-setup / age 0 start;
- age 18;
- age 25;
- age 35;
- age 50;
- age 65;
- final state.

At fixed ages, include only runs active at that age and state that denominator.

For each CHR/INT/STR/MNY/SPR report:
- active N;
- mean;
- median;
- p10/p25/p75/p90/p95;
- min/max;
- shares <=2, <=4, >=12, >=15, >=20;
- mean drift from that run's post-setup stat.

Also report:
- positive authored stat deltas per 1,000 run-years;
- negative authored stat deltas per 1,000 run-years;
- final lower/equal/higher-than-start share.

Do not clamp visible stats in this task.

## Event-frequency / housing telemetry

For the top 25 events by occurrence:
- event ID;
- player-facing English text excerpt/short label in Markdown report;
- occurrences per 1,000 run-years;
- unique-run incidence;
- repeat-within-run incidence;
- mean occurrence count among runs where seen;
- maximum count in one run;
- repeat policy/cooldown/max.

Housing:
identify events through canonical `housing` route tag rather than a hard-coded
single event ID.

Report:
- percentage of runs with any housing event;
- occurrences / 1,000 run-years;
- percentage with 2+ housing events;
- counts by housing event ID;
- average MNY/SPR/other visible-stat deltas generated by housing events.

This should determine whether "move home too often" is:
- one repeatable event dominating;
- the housing family as a whole;
- or small manual-sample variance.

## Low-stat risk telemetry

This is groundwork for the proposed Visible-Stat Pressure layer.

For each visible stat, age 18+, classify each observed annual state:
- critical: <=2
- vulnerable: 3–4
- ordinary+: >=5

For 3-year and 5-year horizons, report conditional probability of:
- any ending;
- Material Commitment;
- any faction transition to COMMITTED.

Use person-year observations carefully and state denominator/method. Do not claim
causation.

This task does NOT add "low stat = death" rules.

## Faction-chain legibility proxy

For each faction:
- contact incidence;
- ENGAGED / COMMITTED / OPTED_OUT / CLOSED incidence;
- faction-caused ending incidence;
- personal faction event counts per contacted faction-run:
  - exactly 1
  - exactly 2
  - 3+
- mean/median gap in years between personal faction events;
- share that opt out/close at the first disposition;
- share that reach an escalation event after ENGAGED;
- share that reach climax after COMMITTED.

Use canonical `factionIds` / `factionInteraction` metadata when available rather
than inferring from English text.

This is a legibility proxy, not proof that prose callbacks are sufficient.

## Profile review

Do not auto-select or write canonical thresholds.

For each arm, discuss:
- completion/nonterminal;
- 18–24, 25–34, 35–44, 45–54, 55–64, 65+;
- ending coverage;
- commitment rate/age;
- route restoration;
- faction terminality;
- late fallback;
- material guardrails;
- visible-stat extremes.

For H2A, a plausible arm will usually:
- move completion toward roughly 45–70%;
- move commitment toward roughly 45–70%;
- bring mean/median commitment toward late 20s / early 30s;
- make 25–34 a major/largest ending bucket;
- substantially reduce survivor-heavy 65+ share.

These are review bands, **not final game targets**.

Do not reject every arm merely because 18–24 remains under the final target: the
future Pressure & Tone patch is expected to add authored adverse early-adult paths.

If no arm looks satisfactory, say so. Do not interpolate a new profile in this
run.
